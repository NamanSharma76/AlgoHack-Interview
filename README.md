
#  AlgoHack Interview

**Live Demo:** [https://algohack-interview.vercel.app/](https://algohack-interview.vercel.app/)

**AlgoHack Interview** is an AI-powered technical interview simulator designed to help candidates prepare for their dream roles. By parsing resumes and cross-referencing them with specific job descriptions, the application generates highly tailored, dynamic interview questions, evaluates user responses in real-time, and provides actionable feedback.

##  Architecture & Tech Stack

This project utilizes a decoupled full-stack architecture, separating the client-facing UI layer from the heavy computational API layer for maximum scalability.

### Frontend: Next.js (Deployed on Vercel)

* **Framework:** Next.js (App Router) + React.
* **Why?** Next.js provides excellent route protection, fast server-side rendering (SSR), and seamless integration with authentication states.
* **Styling:** Tailwind CSS (via `globals.css`) for responsive, utility-first design.

### Backend: Node.js + Express (Deployed on Render)

* **Environment:** Node.js API structured in an MVC (Model-View-Controller) pattern.
* **Why?** Separating the backend ensures that computationally heavy tasks (like parsing PDFs and waiting for AI generation) do not block the frontend UI thread or hit serverless function timeout limits.

### Database & Authentication: Supabase (PostgreSQL)

* **Why Supabase?** An interview platform is highly relational (User ➔ Interviews ➔ Questions ➔ Evaluations). Supabase provides strict PostgreSQL relational integrity, plus out-of-the-box Google OAuth authentication and secure resume PDF storage, acting as a massive force multiplier for development speed.

### AI Engine: Groq + Google Gemini (Smart Fallback Architecture)

* **Primary Engine:** Groq SDK (Llama 3.1 8B Instant).
* **Why?** Groq’s hardware (LPUs) delivers blazing-fast inference, generating conversational responses and evaluating answers in milliseconds for a real-time feel.


* **Fallback Engine:** Google Gemini (1.5 Flash).
* **Why?** Llama 3 has a restricted context window. If a user uploads a massive multi-page resume that exceeds Groq's token limits, or if Groq experiences rate-limiting, the system seamlessly falls back to Gemini's massive 1-million+ token context window to handle the heavy lifting.

## Database Schema

The application relies on a strictly relational PostgreSQL database hosted on Supabase. Below is the core schema driving the logic:

### 1. `users` (Managed by Supabase Auth)

* `id` (UUID, Primary Key)
* `email` (String)
* `created_at` (Timestamp)
* `avatar_url` (String)

### 2. `interviews`

Tracks each unique interview session created by a user.

* `id` (UUID, Primary Key)
* `user_id` (UUID, Foreign Key ➔ `users.id`)
* `job_role` (String) - *The target role (e.g., "Frontend Engineer")*
* `resume_url` (String) - *Link to the parsed Supabase Storage file*
* `status` (Enum) - *'in-progress', 'completed'*
* `created_at` (Timestamp)

### 3. `questions`

Stores the tailored questions generated by the AI for a specific interview.

* `id` (UUID, Primary Key)
* `interview_id` (UUID, Foreign Key ➔ `interviews.id`)
* `question_text` (Text)
* `order_index` (Integer) - *The sequence of the question*
* `created_at` (Timestamp)

### 4. `answers_and_evaluations`

Stores the user's response and the AI's grading feedback.

* `id` (UUID, Primary Key)
* `question_id` (UUID, Foreign Key ➔ `questions.id`)
* `user_answer` (Text)
* `ai_score` (Float/Integer) - *Score out of 10*
* `ai_feedback` (Text) - *Constructive feedback*
* `ai_improvements` (JSONB) - *Array of bullet points on how to improve*
* `created_at` (Timestamp)

## Local Development Setup

To run this project locally, you will need two separate terminal windows (one for the frontend, one for the backend).

### Prerequisites

* **Node.js** installed on your machine.
* A **Supabase Project** (with Google OAuth configured and tables matching the schema above).
* A **Groq API Key**.
* A **Google Gemini API Key**.

### 1. Backend Setup

Navigate to the backend directory and install dependencies:

```bash
cd backend
npm install

```

Create a `.env` file in the `/backend` folder:

```bash
PORT=5000
SUPABASE_URL=your_supabase_url
SUPABASE_ANON_KEY=your_supabase_anon_key
GROQ_API_KEY=gsk_your_groq_key_here
GEMINI_API_KEY=AIzaSy_your_gemini_key_here

```

Start the backend development server:

```bash
npm run dev

```

### 2. Frontend Setup

Open a new terminal, navigate to the frontend directory, and install dependencies:

```bash
cd frontend
npm install

```

Create a `.env.local` file in the `/frontend` folder:

```bash
NEXT_PUBLIC_SUPABASE_URL=your_supabase_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_supabase_anon_key
NEXT_PUBLIC_API_URL=http://localhost:5000

```

Start the Next.js development server:

```bash
npm run dev

```

Open `http://localhost:3000` in your browser to see the application running.

## Core Workflows

1. **Authentication:** Users log in via Supabase Google OAuth on the frontend.
2. **Context Upload:** Users upload a PDF resume. The backend (`resumeController.js`) extracts the text using `pdf-parse`.
3. **Question Generation:** The parsed text is sent to Groq (`questionController.js`). The LLM returns a structured JSON array of highly relevant technical questions.
4. **Evaluation:** As the user answers, responses are sent back to the AI (`answerController.js`) to generate a score, feedback, and improvement points.
5. **Dashboard:** All data is saved to Supabase, allowing users to review their performance history (`historyController.js`) over time.
